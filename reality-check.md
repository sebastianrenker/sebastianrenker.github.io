# RENKER Reality Check

As of: 2026-08-11. Basis: direct checkout and execution of `rencora`, `renkervault`, `continuum`, `renker-core-authz` (state `main`, latest commit at review time each). `renker-core` itself is a **private** repository and was not accessible for this review — see the note at the end.

Methodology: for each claim, code was either read, a test suite actually run, a CI workflow inspected, or a document (SECURITY.md, ROADMAP.md, Wiki) cited as a primary source. No claim in this document rests on mere announcement.

Status values: **REAL** (present in code and verified runnable) · **PARTIAL** (core idea present in code, but limited/incomplete/not externally reviewed) · **PLANNED** (described in roadmap/docs, laid out in code as an interface or TODO, not functional) · **UNVERIFIABLE** (repo not accessible for this review).

## Most important platform-wide findings

1. **No repository claims more than it delivers.** All four reviewed READMEs/SECURITY.md already contain their own "honest limits" sections. That is a real marketing advantage (credibility) and should be continued in new marketing material rather than diluted.
2. **renker-core-authz is the best-substantiated building block** of the whole platform: 88 tests, CI with format/lint/typecheck/test/build/dependency audit, precisely named limits. It should be the workhorse for all "this is not a marketing promise, this is code" statements.
3. **Biggest gap: CI automation is missing for rencora (tests not in CI) and entirely for renkervault (no `.github/workflows`).** Existing tests are real, but do not run automatically on every push — this must not be advertised as "continuously tested" before it is true.
4. **renker-core is private and not accessible for external review/marketing verification.** Any statement about renker-core itself (rather than about its publicly visible consumers) is currently unverifiable from the outside. Recommendation: either (a) make renker-core public, at least the interface/doc layer, or (b) consistently refer in all external communication to `renker-core-authz` as the publicly verifiable core and mention renker-core only as "a private repository, currently the internal reference implementation."
5. **Continuum is the most honest, but also the least "finished" building block.** Simulated data, no hardware, phase 0 of 4. The evidence categorization (`EXPERIMENTAL`/`PREDICTED`/`LITERATURE`) is a strong, real differentiator and should be named exactly that way technically — not as a generic "PROPOSED → TESTED → REPRODUCED → VALIDATED" (that pipeline does not exist in the code in this form).
6. **Rencora is the furthest from its target positioning.** The wiki positioning ("agent runtime with capability security") describes the target architecture; today's code is primarily a feature-rich desktop assistant with an *optional* capability-guard integration. Marketing should phrase this as "on the way to", not as the current state.
